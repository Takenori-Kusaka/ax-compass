# AXコンパス ── AIトランスフォーメーションの現在地診断

経営層が、AI に詳しくなくても、画面を操作しながら次の 4 つを得るための静的 Web アプリです。

1. 自社の現在地(事業フェーズ・導入フェーズ・文化フェーズ)を特定する
2. 目指す未来(3 つの道筋)を選ぶ
3. 次に取るべきステップ、必要なもの(人材・データ・統治・評価・費用)、関わる提供事業者の層、運営モデルの推奨を根拠つきで得る
4. 経営会議に出せる資料(本の第38章の 8 つの見出しの型。A4 で 1〜2 枚)として印刷・保存する

サイト: https://takenori-kusaka.github.io/ax-compass/

本『[AIトランスフォーメーションの設計図](https://zenn.dev/takenori_kusaka/books/ai-transformation-blueprint)』(Zenn)第Ⅴ部の枠組みを GUI にしたものです。本を読んでいなくても使えます。段階の名前と定義は本と同じで、画面の主張ごとに本の章と一次資料への「根拠」リンクを置いています。

## 会議で使うスライド

`public/ax-blueprint-slides.pptx` は、本の各章の図を 1 枚ずつ並べたスライド(40 枚)です。最後の 1 枚は経営会議に出す資料の型(本の第38章)です。サイトの「はじめに」からダウンロードできます。スライドの図の正本は publishing-hub の `images/ai-transformation-blueprint/*.svg` で、図を直したらスライドを作り直します。

## 使い方

1. **現在地診断**: 3 つの軸について、それぞれ 5〜6 問の選択式に答えます。各選択肢が段階に対応し、導入と文化は回答の平均を四捨五入した段階、事業は多数決で決めます。
2. **未来の選択**: 道筋 A(加速)・B(漸進)・C(調整)を、前提・2029 年の像・早期警戒指標とともに提示します。1 つを選ぶか、「決めない(選択権を買う)」を選びます。
3. **悩みの整理**: 経営層の典型的な悩み 18 件から当てはまるものを選びます。各悩みに推奨ステップと本の該当章を対応づけます。
4. **結果**: 本の第38章の会議資料の型(1 現在地 / 2 前提とする道筋 / 3 早期警戒指標 / 4 次の一手 / 5 運営モデル / 6 必要なものと提供事業者の層 / 7 統治の最低限 / 8 答えていない問い)で資料を表示します。8 は自由記述です。印刷(A4 で 1〜2 枚)、Markdown のコピー、JSON の保存と読み込み、共有用 URL の生成ができます。

入力はブラウザの中だけで処理し、外部へ送信しません。`localStorage` に自動保存します。共有用 URL は回答と「答えていない問い」の記述だけを含みます。共有 URL から復元した直後にアドレスバーのハッシュは消し、以後は端末の保存を正とします。個人情報を入力する欄はありません。

## 枠組みの要約

| 軸 | 段階 |
| --- | --- |
| 事業フェーズ | 新規事業(探索)/ 成長 / 成熟(効率)/ 再生(構造転換) |
| 導入フェーズ | S1 触れる / S2 仕事に適用する / S3 仕事に組み込む / S4 システムに組み込む / S5 商品に組み込む / S6 顧客へ届ける |
| 文化フェーズ | C1 禁止・無関心 / C2 個人の試行 / C3 公認の試行 / C4 測って運用 / C5 AI・データネイティブ |

| 項目 | 内容 |
| --- | --- |
| 運営モデル | SaaS 利用 → 集中(CoE)→ ハブ&スポーク → 分散 → 製品組織 |
| 3 つの道筋 | A 加速 / B 漸進 / C 調整。各道筋に「後悔しない手」「選択権を買う手」「賭ける手」 |
| 提供事業者の層 | L1 計算資源 / L2 クラウド AI 基盤 / L3 基盤モデル / L4 業務アプリ内蔵 / L5 開発者ツール・エージェント基盤 / L6 データ基盤・評価・観測 / L7 統治・安全・ID / L8 SI・コンサル / L9 業界特化 |
| エージェントの自律性 | A0 助言のみ 〜 A4 複数エージェントの協調 |

定義の正本は本です。`src/data/framework.json` の定義文は本の表(第0章、第18章、第32章、第33章、第36章)と逐語で揃え、`governanceMinimum` は第37章の手順4(ガイドライン、データ、ID、承認)に基づきます。文言を変えるときは本と同時に変えます。

## 構成

| パス | 役割 |
| --- | --- |
| `src/App.svelte` | 画面遷移、自動保存、URL からの復元 |
| `src/lib/components/` | 各画面(はじめに、現在地診断、未来の選択、悩みの整理、結果) |
| `src/lib/engine.mjs` | 集計、ステップ生成、Markdown、URL の符号化。純関数のみ(JSDoc 型つき JS) |
| `src/data/*.json` | 枠組み、設問、悩み、一次資料 |
| `src/styles/app.css` | 画面と印刷の様式。`brand/` はブランド基盤の複製 |
| `test/engine.test.mjs` | `node --test` による検証 |

## 開発

```bash
npm ci
npm run dev        # 開発サーバ
npm run check      # svelte-check + test + build + brand:check(CI と同じ)
npm run test       # node --test
npm run build      # dist/ を生成
```

GitHub Pages への配信は `.github/workflows/deploy.yml`(main への push と手動起動)で行います。外部スクリプト・CDN・外部フォント・アクセス解析は使いません。
